# R02 身份与对象关系差分

路线目标：从明确的主体、对象和权限关系生成少量高价值实验，验证真正的授权边界。首版聚焦授权测试账号之间的只读对象访问，使用[共用实验协议](共用实验协议与评估.md)。

复核定位：M2 的首项贯通能力，以两个身份、预先准备的受控对象和结构化 HTTP 通道验证四道门。共用 R05 谓词、观察与基线设施，不另建 owner 对照系统，不依赖新控制器。

## 从渗透测试逻辑推导

授权测试的核心不是某个接口返回成功，而是本不应具有某种权限的主体获得了指定对象或执行效果。应先知道谁拥有对象、谁允许共享、操作处于什么状态，再比较不同主体。

使用受控账号和各自创建的受控对象，能减少盲猜对象是否存在的干扰。让拥有者先证明对象存在，再让另一个正常登录的主体执行同一类操作，可以把对象问题、会话问题和权限问题分开。

差分仍需独立的权限预期。公开对象、共享文件或协作者关系可能允许跨用户访问，不能因为 owner 不同或响应相似就上报越权。

## 原设计已有能力与新增机制

[`db/assets.go`](../../db/assets.go) 已支持 Auth、Params 和端点信息，AuthItem 的标准字段包括凭据类型、用户名、密码、token 与说明；这些可作为执行输入。事实和证据也已有记录路径。

新增的是任务内主体与对象关系、权限预期来源、上下文一致的实验构造器，以及按语义效果判断的对照。它不把通用资产中的凭据数组直接当作目标应用完整的角色与租户模型，也不以换一次 Cookie 本身作为创新。

## 数据与实验选择

| 记录 | 最小内容 |
| --- | --- |
| 主体引用 | 稳定主体标识、已确认角色与租户、会话版本及凭据引用 |
| 对象绑定 | 实际对象标识、创建或读取证据、所有权与共享关系、唯一测试标记 |
| 权限预期 | 主体关系、操作、对象、业务状态、允许或拒绝及其独立来源 |
| 请求配方 | 操作和参数位置、主体注入、动态标识与令牌依赖 |
| 结果断言 | 是否读到受保护字段，或是否产生指定业务状态变化 |

权限预期可以来自用户确认的规则、可核对的业务要求或灰盒授权配置；模型提出的规则先作为假设。列表不展示对象、字段名像 owner、其他用户恰好收到拒绝，都不足以独立证明访问应被禁止。

按已发现的关系边界选择实验，例如同角色不同所有者、同操作不同角色、已知不同租户，以及私有与共享状态。对一个边界先生成最小实验，不枚举主体、端点和对象的完整笛卡尔积。

## 对照与判定流程

1. 核对目标范围、已确认权限预期与对象绑定，检查两个主体的登录态。
2. 用对象拥有者建立正常对照，确认受控对象及关键字段确实存在。
3. 以另一主体请求同一对象和操作，保留可比条件，按该主体重新取得必要的 CSRF 或动态令牌。
4. 直接检查对象唯一标记、受保护字段或实际状态变化，必要时重做正常对照排除状态漂移。
5. 只有权限预期、有效性和违规效果同时成立，才形成该边界的漏洞结论；其他情况输出正常拒绝、未复现或无法判定。

变更主体时，其关联令牌可能必须同步改变；否则测到的可能只是请求校验失败。反过来，也不能把拥有者的动态值和对象上下文未经说明地全部转给另一个主体，造成不可解释的多因素变化。

响应长度、状态码和文字相似度可以帮助筛选，不能单独证明越权。字段级接口只对明确受保护的字段下结论，返回公共字段不等于泄露私有内容。写操作要以真实效果判定，并在可重置环境中引入。

## 最小实现与接入

先实现两个测试主体、一个受控对象类型和一个只读断言，主体会话由结构化 HTTP 执行器按引用解析，先保存实际观察，再通过写回门登记摘要和评估。对象映射与身份私有状态归任务所有，不因为资产全局共享而传播。

拥有者对照登记为公共基线的一种用途，绑定对象、主体、状态、权限规则与版本。会话健康和受保护标记匹配只是局部谓词；实际违规需要同时满足独立权限预期、可比条件和效果断言，模型填写 observed 不能代替评估。

可分别创建独立会话和准备对象来隔离其他实验，但跨身份权限比较仍指向同一被测对象。不同主体对同一对象的状态操作需检查共享资源冲突，不能只按 actor 不同判断可并行。

接入 [`agent/tools.go`](../../agent/tools.go) 与 [`agent/worker.go`](../../agent/worker.go) 的实验工具路径，复用 [`agent/finding_workflow.go`](../../agent/finding_workflow.go) 中 baseline、proof、verification 的证据角色及版本约定。

缺少第二个有效身份、对象关系或权限规则时，输出缺失前提和收集建议；不尝试用猜测补齐。共同谓词按能力逐项晋级，门日志和报告同时展示对照、规则来源、实际效果及无法判定原因。

## 分版本交付

| 版本 | 开发范围 | 验收产物 |
| --- | --- | --- |
| R02-V1 | 两个身份、受控对象、明确私有策略、HTTP 只读语义断言 | 四道门贯通记录、原始对照与变更、对象映射、正常与漏洞结果及报告 |
| R02-V2 | 角色与租户、共享例外、动态对象、受控写操作 | 稀疏实验选择器、会话隔离、状态重置及字段级反例 |
| R02-V3 | 将业务状态和对象生命周期接入权限实验，输出下一步建议 | 与 R03 协议联动、条件化结果复用、跨轮收益与成本比较 |

V3 的重点是哪个关系变化值得再测，不是扩大枚举规模。策略版本或共享关系变化时重新检查适用性，不能沿用旧私有假设。

## 最小夹具

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| R02-A | 两个同角色用户，策略规定私有对象，提供正常拒绝与错误放行两个版本 | 只在错误放行并出现受保护标记时报告违规 |
| R02-B | 同一个对象从私有改为合法共享，另有始终公开的对象 | 根据真实策略变化判断，不把合法访问当越权 |
| R02-C | 过期会话、错误 CSRF 或登录页伪装 200 | 判为实验无效或无法判定，不输出安全结论 |
| R02-D | 跨租户对象只返回公共字段，另一个版本额外暴露受保护字段 | 按字段与策略断言区分，而非只比较响应相似度 |

## 有效性依据与失败条件

这条路线的价值在于直接验证权限关系，并消除对象猜测和失效身份带来的不确定性。观察授权违规检出、误报、漏报与准备成本；不能只报告生成了多少测试组合。

如果权限预期来自模型默认、会话无法可靠隔离、共享例外不明确或效果不可观察，就不具备自动确认漏洞的条件。若准备身份与对象的成本超过实际节省，需要缩小到高价值操作。

[OWASP WSTG 的 IDOR 测试](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/05-Authorization_Testing/04-Testing_for_Insecure_Direct_Object_References/)支持多用户与已知对象的测试基础。[AuthMatrix](https://github.com/SecurityInnovation/AuthMatrix)已有用户、角色、请求及动态依赖配置。本路线的增量是将关系发现、稀疏选择、证据判定和计划反馈接入 ARTEX；这些已有方法本身不计作新发明。
