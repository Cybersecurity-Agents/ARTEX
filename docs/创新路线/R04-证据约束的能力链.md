# R04 证据约束的能力链

路线目标：把已经验证的局部行为组合成有前提、有证据、可以实际推进的路线，并优先验证缺失的连接条件。本路线作为后置组合试验，使用[共用实验协议](共用实验协议与评估.md)。

## 从渗透测试逻辑推导

一个局部发现是否有价值，取决于它能让哪个主体对哪个资源获得什么能力，以及能否满足下一步的前提。单个现象可能影响有限，组合后才接近任务目标。

但图上有路径不代表实际能走通。上传成功不证明文件可访问，更不证明可执行；两个服务使用相同技术不证明认证域相同；读到了一个受控对象也不证明能读取所有对象。

因此，组合单元应是带明确条件的已证行为。连接前检查主体、对象、状态、授权与时间条件，只为尚未满足的必要条件生成验证任务，避免让模型用自然语言把空缺补成事实。

## 原设计已有能力与新增机制

现有探索图已经支持多个事实派生意图，Planner 已会串行派发利用链。这些机制见 [`agent/tools.go`](../../agent/tools.go) 和 [`agent/planner.go`](../../agent/planner.go)。

本路线的增量是给关键事实增加受范围约束的能力表达，定义少量可检查的组合前提，并在计划生成前进行相容性验证。它不以多画一张攻击图或增加链路提示词作为完成标志。

复核后作为 M4 的后置能力，先具备公共观察、可验证谓词和计划引用基础，再逐版验证。仍由原 Planner 派发缺口实验，不能因研究能力链而提前开发独立搜索控制器。

## 能力表达与组合约束

| 内容 | 约束 |
| --- | --- |
| 主体 | 实际执行主体与认证域，角色名相同不能自动视为同一主体 |
| 动作与效果 | 区分请求被接受、对象可读取、状态可修改等不同事实 |
| 资源范围 | 绑定具体对象或有证据支持的集合，不从单例外推全量 |
| 成立条件 | 身份、对象、业务状态、依赖与可知的环境条件 |
| 来源证据 | 指向有效实验与可检查断言，模型候选描述不直接升级为已证能力 |
| 适用版本 | 记录何时验证，以及哪些变化需要重新检查 |

组合规则先限定在少量能够观察的对象操作。多个前提必须共同成立，且能够按照实际执行顺序连接；前一步可能改变状态并使旧能力失效，不能只在静态图上做标签匹配。

服务之间的对象编号必须有可靠映射；凭据的 audience、权限与租户条件也需要核对。公司归属、IP 相同、路径名相似或使用相同框架，都不能替代这些证据。

## 路线生成与推进

1. 将经过断言检查的事实登记为受范围约束的能力，保留原始证据与不确定性。
2. 从具体目标反推少量明确前提，与已证能力匹配，列出缺口。
3. 已知不相容的组合不派执行；关键条件未知时，生成验证该条件的任务，不声明链已经成立。
4. 对相容候选，沿现有意图调度逐步推进，每步输出后重新检查后续条件。
5. 新反证或上下文变化进入复核，保留历史路线，不继续复用已失效前提。

例如受控服务 A 为测试文档生成只读分享凭据，服务 B 若接受该凭据修改同一文档，需要证明凭据可取得、资源映射一致、凭据权限确实只读，以及 B 产生了真实写入。只知道 A 与 B 都有同名文档或都使用某种 token，无法形成该链。

目标优先级可以帮助选择缺口，但不必先引入虚构成功概率。V1/V2 根据目标相关性、缺失前提数量、已知验证成本与约束排序，并保留 Planner 提出其他开放方向的能力。

## 最小实现与接入

V1 人工审核少量能力记录，限定主体、对象读取和状态修改等语义，不自动将所有漏洞名转换为执行能力。组合器只输出相容、不相容或缺少哪些前提。

V2 接入现有意图工具验证一个缺口，来源记录可由 R02/R03 等路线产生，也可由独立的有效实验人工确认。相容性检查依据共用协议，不要求等待所有路线集成。

接入 [`db/exploration.go`](../../db/exploration.go) 的现有图存储及 [`agent/tools.go`](../../agent/tools.go) 的派发路径，保存能力与来源引用，不建立另一个权威事实库。跨目标动作仍须逐项检查用户授权范围，知识关联不代表执行许可。

复用 R05 的公共检查与基线，组合规则也按机器谓词逐项登记和验证。引用上下文变化后由派发与领取门复查；写回和目标完成使用共同规则。日志与报告区分已验证边、未知连接和被拒绝的组合，不把路径存在写成已实现影响。

## 分版本交付

| 版本 | 开发范围 | 验收产物 |
| --- | --- | --- |
| R04-V1 | 人工已证能力、少量组合规则、主体对象与状态相容性检查 | 可执行和虚假组合的离线反例；只输出建议 |
| R04-V2 | 针对单个缺失前提派验证任务，执行后重新规划 | 单条真实可执行链、前提不足时的阻塞处理、完整验证成本 |
| R04-V3 | 多事实组合、证据变化后的增量修订、有限深度路线比较 | 与自由规划及关闭组合器的对照评估，链路失效复核与回退 |

自动从自然语言抽取能力可以作为候选生成，但已证标签必须经过对应断言。规则未覆盖的能力保留为普通事实，由 Planner 自由探索，不强行套入类型。

## 最小夹具

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| R04-A | 两个授权测试服务，同一受控对象，合法只读凭据在第二服务错误获得写入效果 | 逐项验证对象与权限连接，实际观察效果后确认链 |
| R04-B | 两个命名相同但属于不同认证域或对象命名空间的记录 | 拒绝虚假拼接，不以文字或编号相同作为连接依据 |
| R04-C | 前一步改变对象状态，导致后一步原有能力失效 | 重新检查前提，不能用旧能力宣告链成功 |
| R04-D | 一条路线缺少关键映射，另有证据完整的可执行路线 | 未知映射只生成补测；完整路线仍可推进，不被未知分支拖住 |

## 有效性依据与失败条件

多阶段问题需要考虑多个元素的相互作用，这一动机有 [MulVAL 的原始研究](https://www.usenix.org/conference/14th-usenix-security-symposium/mulval-logic-based-network-security-analyzer)支持。该研究不证明本方案的动态能力抽取或 LLM 组合已经有效；本路线必须先验证类型与前提检查是否可靠。

主要指标是有证据且实际走通的链、虚假拼接率、关键前提验证成本与最终目标产出。图上路径数、链长和模型生成的解释都不能替代这些指标。

若自然语言能力规范化错误频繁、规则维护成本高于有效组合收益、或大量目标只能靠未经验证的连接成立，则保留人工建议，不扩大自动执行。它应在前提表达与证据质量已有基础后推进。
