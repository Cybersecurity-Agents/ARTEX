# R01 条件化假设与计划修订

路线目标：让探索结论只在有依据的条件下复用，让反证触发准确的计划修订。版本与模式遵循[共用实验协议](共用实验协议与评估.md)。

复核定位：前期以观察模式参与 M0 审计；完整修订在 M3 沿现有 Planner 接入。M1 先设计计划依据和预期产出引用，M2 先检查显式依赖版本，不等待全量语义冲突识别，也不引入新控制器。

## 从渗透测试逻辑推导

一次测试没有成功，至少可能意味着方法不适用、前置条件不成立、观察不到效果，或者这个具体条件下确实未复现。把这些结果都写成目标不可利用，会提前封死路线；完全不记负结果，又会反复做相同测试。

因此应保存的是带条件的结论：在某个身份、对象、业务状态、测试方法与观测能力下，观察到了什么。后续任务复用的是这些条件内的知识，而不是一句全局否定。

正向假设也一样。两个接口可能共享认证机制，只是一个待验证解释。若计划依赖这个解释，新证据推翻它时，系统应找到依赖它的计划，而不是继续沿用旧理由。

## 原设计已有能力与新增机制

[`agent/planner.go`](../../agent/planner.go) 已要求查看弱否定证据、限制同方向复核、在有材料性新机理时重派，并用待办分步推进链路。[`agent/tools.go`](../../agent/tools.go) 已保存置信度及事实到意图的来源关系。

本路线增加条件化的结论、显式的决策依据和依据变化后的修订流程。它不只是持久化待办，也不以更换总结提示词作为完整实现。

## 核心表达

| 记录 | 需要保存的内容 |
| --- | --- |
| 原始观察 | 实际输出、时间、上下文与证据引用，保留历史 |
| 条件化结论 | 断言、适用条件、采用的方法、观察能力、支持与反驳证据 |
| 计划依据 | 某条待办或意图依赖哪些结论，依据版本是什么 |
| 修订事件 | 什么变化触发复核、影响哪些方向、Planner 如何处理 |

观察、解释与适用性分开。例如某时刻用户 B 访问对象 X 被拒绝，是历史观察；所有用户都不能访问 X 是额外推断，不能从该观察直接得出。

只有已实现断言或人工确认的反证才支持正式标记某个依据失效。模型提出的疑似冲突先登记为复核候选，不直接改变真值、阻断执行或撤销目标证明；由已注册规则或明确人工决定进入阻断性复核。程序检查发现必要条件未知时，按自身规则暂缓。

复核状态属于新协议，不能把新状态字符串直接写入现有探索节点的状态枚举。

## 决策与修订规则

1. 关键计划写明可定位的依据，允许存在多组独立且充分的依据。
2. 新证据先比较身份、对象、状态、方法和环境条件。条件不同的结论不自动构成矛盾。
3. 对适用条件内的反证，定位受影响计划；如果另有独立依据仍成立，保留它并提示变化。
4. 全部有效依据丧失、或者依据是否适用无法确认时，进入复核，由 Planner 选择继续、修改、暂停或放弃。
5. 重开已测方向时记录材料性变化与新的验证目标，按同一条件下的预算控制重复执行。

刷新了一次 token 不一定构成新机理；同一主体、权限和有效性未改变时，不应因此重测。登录态从失效恢复有效、角色或租户关系改变、发现新的必要参数，则可能改变旧测试的适用性。

同样，存在过一次拒绝响应不意味着以后都应封住这条路线。复用负结论时必须检查其方法、前提和观测条件；信息缺失时保持未知。

## 最小实现与接入

V1 只对少量关键假设人工确认上下文与依据，用已有事实编号关联待办或意图，观察哪些变更应触发复核。先验证条件匹配和影响定位，不做全量自然语言真值推断。

后续在任务所属记录中保存依据版本和复核待办，复用 [`server/manager.go`](../../server/manager.go) 的 TriggerEvent 与 debounce 唤醒 Planner。它们用于通知，现有内存事件不是持久依赖机制；先提交变化与待复核记录，启动或恢复时扫描未处理项，避免丢通知就丢修订。

派发与领取门检查所引用依据的版本。进入待复核状态的必要依据不能被当作已经成立；有其他独立充分依据时按明确规则继续。模型只能提出语义冲突与处理建议，不能自行制造机器反证或覆盖失效结果。门日志保存受影响引用、采用规则和实际决定。

原始事实与修订历史保留，关联任务的来源记录保持只读，不能把来源任务的条件直接视为本任务条件。观察级上下文由公共记录提供，不从已经汇总丢失的 detail 猜测重建。

使用 R05 的公共有效性谓词与基线；独立开发时可用同一协议的固定实现，不等待所有诊断策略完成。路线开关和谓词判定权分别验收。

## 分版本交付

| 版本 | 开发范围 | 验收产物 |
| --- | --- | --- |
| R01-V1 | 关键结论与计划依据关联，条件差异观察，人工确认语义冲突 | 输入输出示例、影响定位结果、同条件与异条件夹具；只观察不自动重派 |
| R01-V2 | 持久化依据版本、多组依据与复核待办，复用触发器并实施恢复扫描 | 过期写入拒绝、丢通知与重启后的复核、派发和领取决定日志 |
| R01-V3 | 条件化负结果复用、有材料性变化的受控重开、目标依据复核 | 跨轮对照评估、重复预算、目标结论受影响时的复核路径 |

V3 不自动删除历史发现，不把一条可能冲突的语义判断级联为所有下游目标失败。无法确定支持或反证关系时保留原证据，交给复核。

## 最小夹具

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| R01-A | 失效会话产生否定观察，随后恢复有效会话并满足测试前提 | 旧否定不封死新条件，生成有区别的复核方向 |
| R01-B | 同一有效身份仅刷新 token，其他适用条件未变 | 不因无关版本变化重复重开 |
| R01-C | 计划有两组独立充分依据，其中一组被反驳；通知丢失后重启 | 保留仍成立的依据；两组都失效时要求复核，恢复不遗漏待办 |
| R01-D | 不同租户或不同环境产生相反观察，另有一组条件不明记录 | 不误判为同条件矛盾；条件不明保持未知 |

## 有效性依据与失败条件

收益来自限制结论外推和准确处理依据失效，两者均可在夹具中判定。主要指标是错误续派减少、合理重开没有遗漏，以及为此增加的模型与验证成本。

若标签匹配依赖不稳定的文字相似度、任何环境变化都导致全量重测，或者保守规则持续阻止原实现已成功的方向，则该版本不进入自动执行。

理论参考是 [de Kleer 的 An Assumption-based TMS](https://www.dekleer.org/Publications/An%20Assumption-Based%20TMS.pdf)：结论可以与其成立所依赖的假设集合关联。本路线借鉴条件与依据维护，不直接引入完整 ATMS，也不将该理论的性质当作 LLM 语义判断的保证。
