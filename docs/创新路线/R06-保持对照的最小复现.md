# R06 保持对照的最小复现

路线目标：把已发现问题变成保留原证明关系、能在独立环境复现的最小必要实验，并用于后续修复验证。约简依照[共用实验协议](共用实验协议与评估.md)，不追求单纯最短请求。

复核定位：随 M3 的已有复测与证据工作流推进，复用公共基线、机器谓词及执行通道，不等待其他路线全部完成，也不另建报告或控制循环。

## 从渗透测试逻辑推导

一个问题在长会话中出现，不代表移交其中最后一条请求就能复现。必要条件可能包括对象创建、特定身份、一次业务状态变化或前置令牌，其他请求则可能完全无关。

约简应删除不必要内容，同时保持原漏洞的因果与权限关系。若删除身份字段后只是得到另一个错误页，或者换了对象后读到的是公共数据，虽然响应仍有异常，也没有保留原证明。

因此，约简每一步都要同时检查正常对照、原违规效果和关键语义条件。环境无法可靠重复时先停止，不把偶然结果压缩成看似简洁的 PoC。

## 原设计已有能力与新增机制

现有证据设施会保存快照与版本，报告 Agent 可核对证据，独立复测 Agent 已要求最小针对性验证。这些机制见 [`evidence/store.go`](../../evidence/store.go)、[`agent/finding_workflow.go`](../../agent/finding_workflow.go) 和 [`agent/retester.go`](../../agent/retester.go)。

新增的是约束明确的自动约简器，以及由约简结果形成的可执行复现实验。它不只是再增加一位报告或复核 Agent。

## 约简时必须保持的条件

| 条件 | 验证内容 |
| --- | --- |
| 正常对照 | 原来允许的操作仍能得到预期正常效果 |
| 原违规断言 | 相同类型的受保护数据或业务效果仍被观察到 |
| 主体与关系 | 身份、角色、租户、对象所有权及权限预期保持可比 |
| 必要前置 | 动态标识、令牌、状态和观察渠道仍成立 |
| 独立复现 | 可从声明的初始状态开始，不依赖未说明的会话残留 |

允许在新夹具中生成新的对象编号和会话，但必须保持对应关系和语义条件。响应码相同、同样出现异常字符串或仍产生某个 500，不足以证明仍是原问题。

## 约简流程

1. 读取原始证据、实际执行轨迹和明确的漏洞断言，列出不能删除的语义条件。
2. 在可重置环境验证原实验及正常对照，建立可重复基线；原实验无法复现时先诊断，不开始自动约简。
3. 先尝试移除与目标无关的序列片段，再约简可独立删除的参数与结构化字段。对象生产与消费依赖必须一起考虑。
4. 每次候选在干净且可比的状态下执行，只有正常对照与原违规断言同时满足才接受。
5. 在预算内输出当前已验证的约简结果、保留条件和未决内容，不承诺全局最小。

签名、CSRF、对象创建等字段不能通过任意字符串删除处理。解析后重建或重新生成必要动态值，若暂不支持对应协议就保护该结构。异步、缓存和概率性结果需要额外的重复性设计，不默认视为确定判定器。

原始证据保持不变；约简实验是新的派生记录，附带来源与证据版本。脱敏展示与原始证据分开，不能改写原报文后仍宣称是实际请求。

## 最小实现与接入

V1 读取一个已明确判定的 HTTP 或小序列案例，人工确认不可删除条件，离线产生约简候选。没有重新执行的候选明确标为未验证，不更新漏洞结论。

V2 在可重置夹具上接入判定器与依赖感知约简。写入或状态恢复不确定、正常对照失败、证据版本变化时，停止接受新候选并保留已验证记录。

优先支持结构化 HTTP 请求和小流程，复用会话、对象依赖和正常对照记录。其他通道的证据按来源与可核对性判断；尚无可靠解析与效果判定器时保护原结构，保留建议，不盲目删除命令或字段。

报告更新沿用现有 evidence_version 检查。V3 可以把复现配方交给已有独立复测路径，但约简配方单次未复现不能自动判 fixed；需要核对原触发条件、可比环境与正常对照。

约简执行也经过共同的准入、写回和完成规则，记录接受或拒绝候选的判定依据。报告同时提供原始证明、已验证约简及剩余条件；实验的 not_reproduced 与既有复测 verdict 分别保存。

## 分版本交付

| 版本 | 开发范围 | 验收产物 |
| --- | --- | --- |
| R06-V1 | 明确漏洞断言、锁定保护条件、结构化约简候选 | 原始与候选差异、不可删除条件、未重验证标识 |
| R06-V2 | 可重置环境中的对照保持约简、序列依赖与预算 | 每一步候选的真实结果、独立复现实验、语义保真反例 |
| R06-V3 | 保存复现配方，接入复测与回归版本 | 新会话和新受控对象的复现、修复与干扰版本对照、历史证据追溯 |

对真实目标重新执行约简需要沿用任务原有的范围与操作约束。首轮自动约简仅在具备重置手段的测试环境验证；缺少该能力时保留建议模式。

## 最小夹具

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| R06-A | 请求有多个无关字段，但必须保留主体、对象及一个关键输入 | 删除冗余后仍保留相同违规断言和正常对照 |
| R06-B | 删除身份条件后进入另一个同状态码页面 | 拒绝该候选，不能把页面相似当作原漏洞复现 |
| R06-C | 只有创建对象和状态变更完成后才能触发，多余查询可以移除 | 保留生产消费与状态依赖，生成完整复现配方 |
| R06-D | 环境漂移、偶发结果或重置失败，原始证据版本另有更新 | 退出约简或重新核对，不凭单次失败标记已修复或覆盖新报告 |

## 有效性依据与失败条件

约简机制参考 [The Debugging Book 的 Delta Debugging](https://www.debuggingbook.org/html/DeltaDebugger.html)：移除输入的一部分，再检查原失败条件是否仍成立。本路线增加权限关系、正常对照与业务效果的联合约束，避免把任意异常当作同一问题。

主要收益是独立复现更可靠、必要条件更清晰和修复验证更准确。需要报告约简的额外请求与重置成本，不能将更短的报文直接计作发现能力提升。

如果判定器只匹配状态码、无法保证对象与权限关系、原实验不可重复或恢复过程有残留，则不执行自动约简。对这些场景保留完整证据和人工复现路径。
