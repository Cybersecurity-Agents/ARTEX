# 创新路线共用实验协议与评估

复核更新：2026-10-16。状态：待实施的共用契约，沿现有 Planner 和 Worker 接入。

六条能力方向共用实验语义、谓词与基线设施，其中 R05 承担公共有效性检查和诊断。协议的目标是让一个结论可以回答：谁在什么条件下，对哪个对象做了什么，实际观察到了什么，为什么足以得出这个结论。它不依赖独立搜索控制器。

## 最小数据契约

### 实验上下文

| 字段 | 含义与约束 |
| --- | --- |
| task_id 与 exploration_id | 显式区分任务与探索记录的编号，校验归属 |
| authorization_revision | 用户授权范围的版本；动态发现资产不自动扩大授权 |
| target_ref | 精确目标引用，保留协议、主机、端口及必要路径信息 |
| actor_ref 与 session_revision | 主体及其当前登录态版本；凭据由执行器按引用解析 |
| object_refs 与 relation_refs | 测试对象、所有权、租户和共享关系及其依据 |
| application_state_ref | 业务前置状态及其观测记录，不以口头描述替代 |
| environment_revision | 可知的部署、配置或测试环境版本；无法确认时注明未知 |
| observation_channel | 实际可用的响应、状态读取、日志或其他观测渠道 |

不把 token、Cookie 和密码复制到全局事实摘要。首次实现可以使用任务内引用映射到现有凭据配置，不需要同时重建整个凭据管理系统。不能仅凭角色名、同一 IP 或同属公司就认定主体、认证域或授权相同。

### 实验记录

记录实验标识、来源意图、假设与依据引用、正常对照、变更因素、操作序列、预期断言、观察引用、请求与模型预算，以及需要时的重置办法。

共用记录保存 schema_version，路线输出保存 route_id 与 route_version，运行时另记模式。协议版本和研发里程碑分开，新增可选字段保持旧记录可读；历史记录没有的上下文保持未知，不用模型批量猜测回填。

控制请求和变更请求绑定相同上下文版本。登录态、对象或业务状态变化后，重新检查适用性。随机令牌和动态标识通过明确依赖提取，不用模型猜测前一个请求产生了什么。

### 观察与计划引用

观察明细由受支持执行器先保存，至少包含执行及尝试标识、实际目标、上下文引用、时间、观测渠道和原始记录引用。模型随后生成摘要，不能成为这些字段的唯一来源。fact 可以聚合多条观察，断言仍分别绑定实际适用条件。

已有 `record_fact` 的汇总要求属于模型工具说明，不是数据库合并。迁移时保留历史正文和未知条件，不用模型恢复并未记录的对象或会话。敏感明细沿现有权限读取，不将凭据复制到全局摘要。

计划步骤保存 `step_id`、`plan_revision`、依据引用和 `expected_output_refs`。未来产出采用步骤与输出键形成的占位引用，实际执行后绑定观察或断言；不得用不存在的 fact ID 表示未来事实。进度由运行状态和有效绑定派生，支持撤销绑定后的复核，不能只持久化一个已勾选标志。

### 断言与实验结果

断言至少包含被检查的规则、规则来源、实际可观察的条件和证据引用。程序只能自动判定已实现的断言；模型提出的权限规则或业务规则在未经确认前属于待验证假设。多项观察可以经有来源的推导支持结论，不能只根据 `observed/inferred` 标签准入或拒绝证明。

| 结果 | 含义 |
| --- | --- |
| violation_observed | 在有效条件下观察到已定义规则被违反，证据满足该断言 |
| not_reproduced | 本实验与当前条件下未复现，不能外推为目标整体安全 |
| inconclusive | 前提、对照、观测或证据不足，无法形成肯定或否定结论 |
| not_applicable | 已有依据证明该测试方法不适用于当前条件 |

这些是新实验协议的结果，不直接替换现有 intent 状态、confidence 或漏洞复测的 verdict。由适配层明确映射：例如 inconclusive 不映射为 fixed，not_reproduced 不自动关闭整条探索路线。

引用漏洞时保留 finding_id 与 finding_node_id 的区别，沿用现有接口约定。结果写入图或报告时校验来源任务、引用权限和证据版本。

## 谓词权威与四道门

| 类型 | 必需内容 | 权限 |
| --- | --- | --- |
| 机器谓词 | 注册名称与版本、输入类型、适用条件、观察要求、程序结果及原因 | 仅在已验证范围内参与准入、失效判断和结论升级 |
| 模型标注 | 来源、解释、候选条件、相对评分及待验证内容 | 作为建议或复核线索，不能自行获得判定权 |

机器谓词结果可为 true、false 或 unknown；它们是局部条件值，不直接等同于实验四值结果。例如状态码匹配成功不等于权限违规。判定器需组合有效身份、对象关系、独立权限预期和实际效果，才能形成相应断言。

评估记录由程序产生，绑定输入观察、上下文与规则版本；模型只能引用，不能提交一个同名 JSON 对象就冒充已验证结果。已知前提失效或缺少必要证据时，不能通过修改文字标签恢复有效。

模型可登记复核线索，不直接改变依据有效性或制造阻断状态。是否进入阻断性复核，由已注册规则或明确人工决定；必要条件为 unknown 时按程序规则处理，避免开放标签获得实际准入权。

四道门分别在派发、领取、写回和完成处调用共同规则，业务状态及必要关系原子提交。领取时重新检查版本，但关键请求前仍需按支持能力复查目标实际状态；数据库检查不能保证外部环境不变。详见[主架构职责](../问题驱动的实验搜索架构.md#四道门的职责)。

封闭谓词集合约束自动判定，不封闭探索策略集合。未知方法可以进入建议、前提准备或有边界的探索，未经实现的断言不能直接升级为已证明目标。

## 有效性检查的分层

| 层次 | 检查内容 | 不能据此推出的结论 |
| --- | --- | --- |
| 传输 | 是否实际收到对应目标的完整响应 | 收到响应不代表已进入目标业务逻辑 |
| 身份 | 对需要登录的实验，主体与会话是否有效 | 健康检查返回 200 不证明登录有效 |
| 业务基线 | 合法对照能否产生预期业务结果 | 单次合法成功不证明所有参数与后续状态都有效 |
| 观察能力 | 是否能看到本实验要验证的效果 | 没有可见回显不代表没有效果 |
| 方法适用性 | 当前实验方法与已知目标条件是否相容 | 黑盒响应不能普遍证明到达了特定代码分支 |

各实验声明实际需要的检查项。匿名公开接口不强制要求登录；缺少某项观测时输出未知，不补造前提成立的事实。正常对照优先使用已知可用的最小读取，在批次边界、上下文变化或异常出现时复查，控制额外开销。

## 共用基线记录

R02 的 owner 对照、R03 的正常业务流程和 R05 的会话健康共用基线存储、引用、复查和失效机制，各自保留用途及判定器。正常流程可达不能证明业务顺序必须遵守，会话有效也不能证明拥有指定对象。

基线绑定目标、主体与会话、对象或业务状态、用途、观察引用及谓词版本，记录有效期和异常失效条件。目标授权或环境变化后重新检查；服务端无本地通知的状态变化通过到期与异常复查处理。同一上下文编号不能无限延长有效性。

基线创建与恢复请求均计入预算，不能为六条路线分别重复建设并隐藏准备成本。复用前先判上下文是否相容，任务私有会话和对象不因共享资产图而自动传播。

## 与现有架构的接入

| 位置 | 接入职责 |
| --- | --- |
| agent/planner.go 与 agent/tools.go | 提出实验、接收结构化结论，派发与完成走共用领域规则 |
| agent/worker.go | 执行实验并返回实际观察，继续承担一条意图的职责 |
| db 与现有证据存储 | 持久化上下文、版本及关系，引用原始记录与快照 |
| agent/retester.go 与 server/finding_retests.go | 复用独立复测及 reproduced/fixed/inconclusive 的现有处理 |
| agent/finding_workflow.go | 复用 baseline/proof/verification 证据用途与报告版本检查 |
| server/engine.go | 沿现有调度路径领取与执行实验，检查前提、预算与通知 |

实现时可增加小型实验领域模块，先定义上述契约，再由现有 Agent、数据库和执行器适配。保持单一业务状态来源。新路线的检查只覆盖通过这些实验接口执行的动作，不能宣称已覆盖任意 Bash 或所有第三方工具的行为。

模块边界可以按下表组织，目录名称为开发建议，当前仓库尚未包含这些新增模块。

| 建议模块 | 职责与依赖 |
| --- | --- |
| experiment | 共用引用、上下文、实验结果与断言接口；不依赖 agent、server 或具体数据库 |
| experiment/predicate | 公共机器谓词注册、适用性与评估记录 |
| experiment/baseline | 各用途基线的引用、版本、期限与复查契约 |
| experiment/belief | R01 的依据维护与复核定位 |
| experiment/authorization | R02 的关系选择与差分实验 |
| experiment/workflow | R03 的状态、依赖与不变量 |
| experiment/capability | R04 的能力表达和组合检查 |
| experiment/validity | R05 公共有效性检查及有预算的原因鉴别策略 |
| experiment/reduction | R06 的保真约简与复现配方 |
| 现有 db、agent、server | 分别承担持久化适配、工具适配与任务内装配 |

路线模块依赖共用契约，通过接口消费其他路线的能力，避免互相读取私有表或形成循环依赖。共用契约与必要的存储适配先集成，各路线版本再分别接入工具注册与任务装配。新增字段的迁移由存储适配统一处理，关闭开关不删除历史实验。

首个协议原生执行通道为结构化 HTTP，负责身份注入、动态依赖、对照关联与实际请求响应记录，复用已有证据设施。流量捕获关闭、非 HTTP 或代理未覆盖时，使用执行器实际提供的原始记录；不存在记录就不能虚构证据，也不为启动路线自动打开全局捕获。

Bash 保留为通用通道。证据质量按来源、完整性、上下文和可核对程度判断，不能仅按通道分高低。缺少结构化身份、效果模型或可重放性时明确降的是哪项能力，不能宣称其观察已通过对应检查。

优先新建会话或受控对象以隔离独立实验，仍对共享资源比较实际读写冲突。冲突记录包含认证域、主体、对象集合和状态域，不同主体对同一对象的写入也可能冲突。模型不能缩小执行器已知的副作用范围；未知写入先对账，不直接重试。

持久依据和复核待办先写入，再复用 TriggerEvent 与 debounce 唤醒 Planner。恢复时扫描待复核记录，不依赖内存事件完整留存。

## 门日志与分级呈现

每项新判定器与日志、报告适配同步交付。门日志记录门类型、允许或拒绝等实际决定、相关意图或目标、依据与上下文版本、谓词版本、原因及后续复核引用。允许状态转移的决定随业务事务保存，关键记录失败时不返回成功；日志不能虚构对未评估候选的比较。

呈现区分候选解释、有来源观察、规则验证结论及独立复现，附各自条件与引用。它们表达不同保证，不能由模型自行贴标签升级，也不折算成无校准的置信分数。`not_reproduced` 展示有效对照、测试方法和适用范围；条件不足应为 inconclusive，不能显示为已修复。

沿用现有证据版本和复测界面。新实验四值结果、节点工作流状态、模型 confidence 和复测 verdict 分别保存，通过明确适配联系，避免四套概念混成一个状态字段。

## 模式与回退

| 模式 | 行为 |
| --- | --- |
| off | 不参与规划和执行 |
| observe | 分析已有轨迹或夹具，不发额外目标请求，不改变原决策 |
| suggest | 输出带依据的实验建议，经现有调度与权限路径执行 |
| execute | 仅在已支持的前提、操作类型和预算内自动执行 |

每条路线使用独立开关与版本号。关闭后停止新增路线动作，保留已经产生的证据和版本。正在执行的外部操作不能靠切换开关撤销，其归属和结果仍需要正常收尾。

谓词另外登记观察、建议或强制检查的权限阶段，按输入类型和判定能力逐项验收。某路线进入 execute 不代表它提出的所有谓词都已获权；观察中的新检查不改变旧决定。实验路线开关不关闭引用归属、事务、完成权限等基础规则。

## 对照评估设计

架构评估沿用[架构文档的四组定义](../问题驱动的实验搜索架构.md#原型版本与对照评估)：E0 原实现、E1 可靠性加固、E2 门化 Planner 主交付物，以及仅在准入后建设的 E3 独立控制器。E2 与 E3 共用同版本路线和检查器，只改变候选选择与预算分配。

选择权对照固定候选生成协议、信息和候选上限；更换生成器或扩大搜索另作消融，避免把输入质量改善误记为控制器增量。

单条路线与同一阶段关闭该路线的实现比较；组合时逐项消融。R05 公共检查与主动诊断分别计量，R03 可达性与有来源规则下的违规判定分别计量，避免把更强规则输入、更多预算或基础修复的收益记到算法上。

固定模型、提示词版本、任务输入、账号、对象、服务初始快照和预算，记录每次实际故障切换。配对运行前重置服务，避免先运行的一组改变后一组的测试条件；随机化组的执行顺序，重复观察结果分布。

离线轨迹只能验证分类、引用和计划修订逻辑，不能证明额外请求能发现更多问题。发现能力必须在可重置、带已知真实规则的服务中验证。评估器持有隐藏的实现与漏洞标签；任务明确提供的业务规则、测试账号及对象创建观察，可以作为新旧两组共同输入。

有明确规则的样本与缺少规则的纯黑盒样本分开统计。后者不能偷偷向新方案补充策略，也不能只保留前者来宣称整体效果。缺少规则时应保留待确认状态，并统计它对任务产出的影响。灰盒条件另行分组。

## 夹具要求

每条路线文档列出四类最小夹具。每类都应有适用与不适用、正常与违规或干扰条件的对应版本，并包含能使原判断器出错的反例。它们是待实现的测试要求，不是已完成的运行记录。

测试对象使用受控账号、唯一标记和可重置业务数据。需要写操作的夹具在隔离测试环境执行，并验证清理或恢复确实完成。这里的限制来自实验可比性和状态可靠性的需要。

## 晋级与停止条件

V1 先验证判定逻辑与记录语义；V2 再比较实际执行效果；V3 研究跨轮和跨路线组合。每次晋级前固定本版指标和额外预算，不在看到结果后调整成功定义。

自动执行至少满足：固定正确性夹具通过；正常场景不增加误报；干扰被识别为无法判定；未丢失原实现已成功的目标；路线主指标在配对重复中表现稳定；总成本符合本版预算。样本不足时只报告观察，不宣称统计上显著或普遍有效。

| 路线 | 主指标 | 必须同时报告 |
| --- | --- | --- |
| R01 | 错误依据后的续派、合理重开与修订正确性 | 不必要重开、漏掉有效方向、修订成本 |
| R02 | 已知权限策略的违规检出 | 误报、漏报、无法判定、身份与对象准备成本 |
| R03 | V1 的有效状态可达性；有来源规则下 V2 的违规检出 | 复位失败、无效序列、规则缺失、漏报和执行成本 |
| R04 | 实际可执行且到达目标的能力链 | 虚假拼接、缺前提路径、验证请求与模型成本 |
| R05 公共能力 | 无效测试被误解释为安全的次数 | 可判定比例、诊断恢复收益、额外请求和共享基线成本 |
| R06 | 独立环境复现成功与证明关系保真 | 约简请求成本、丢失必要条件、无法约简的比例 |

所有控制、鉴别、复核和约简请求都计费；同时记录工具、模型与人工补充成本。发现阶段与复现阶段分别记账，再报告总计。提高无法判定比例、缩短报告或产生更多节点，本身都不构成效果提升。

若收益仅来自更多请求、错误推断规则、忽略无法判定样本、改变目标定义或不完整的环境重置，则停留在当前模式，修正实验后重新比较。

## 任务目标与有原因的停止

按预算内有充分证据的目标产出评估效果，同时报告错误完成、有效实验、探索与证明等待以及准备成本。现有粗略资产覆盖率不能替代测试充分性；量化验收需要明确指标、分母和规则版本。

预算、无法恢复的前提阻塞或预登记窗口内的低边际推进可以结束探索，分别保存终止原因和未覆盖内容。未新增事实只触发策略复核；有限替代策略和成本限制用于决定是否继续，不构成“已测透”的证明。

新控制器的开始与采用门槛以[架构文档](../问题驱动的实验搜索架构.md#什么时候才需要新控制器)为准。公共协议、四道门与六条能力方向均可在现有循环中交付。
